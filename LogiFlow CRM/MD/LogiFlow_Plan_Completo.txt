1) Visão geral do projeto
------------------------
Objetivo: Construir um CRM SaaS white‑label especializado para transportadoras e logística,
baseado no SuiteCRM, com interface Vue, backend Python e provisionamento multi-tenant.
Nome temporário: LogiFlow CRM.

Produto final: uma plataforma com branding próprio, módulos especializados de transporte,
workflows automatizados, dashboards operacionais e financeiros, integração com WhatsApp/VoIP,
sistema de cobrança automatizada (Stripe/Asaas), e oferta de hospedagem e suporte.

2) Por que usar SuiteCRM como base
----------------------------------
- Fornece o motor (autenticação, usuários, ACL, módulos, API, workflows, temas, etc.).
- Reduz ~90% do tempo de desenvolvimento comparado a criar do zero.
- É open-source e permite rebrand e monetização sem royalties.
- Comunidade e plugins prontos aceleram entregas.
- Mantenha customizações no diretório /custom para facilitar updates.

3) Arquitetura técnica recomendada (produção SaaS)
-------------------------------------------------
Camadas principais:
- Frontend: Vue 3 (Vite), Pinia, Vue Router, Axios.
- Backend orquestrador: Python (FastAPI) — autenticação, billing, regras de negócio, integração com SuiteCRM API.
- SuiteCRM: PHP (7.4/8.0), MySQL/MariaDB — armazena dados de CRM e módulos custom.
- Cache/Queue: Redis + Celery / RabbitMQ (para jobs assíncronos).
- Storage: S3 ou MinIO para attachments e backups.
- Observability: Prometheus + Grafana; Sentry para erros.
- Proxy/API gateway: Nginx/Traefik (SSL, CORS, rate-limit).

Recomendações:
- Autenticação SuiteCRM V8 (OAuth2) para token-based access.
- Backend Python faz cache dos tokens e renova automaticamente.
- Isolamento por tenant recomendado via DB por tenant (recomendado) — mais seguro para restore e compliance.

5) Estratégia SaaS / multi-tenant (opções e recomendação)
--------------------------------------------------------
Opções de multitenancy:
A) DB por tenant (RECOMENDADO) — melhor isolamento, backups por cliente.
B) Single DB + tenant_id — menor custo, maior complexidade para isolamento e compliance.

Provisionamento recomendado (DB por tenant):
1. Criar banco novo a partir de um template (schema dump).
2. Criar usuário e permissões MySQL específicas.
3. Criar bucket S3/prefixo para attachments.
4. Registrar tenant no Admin central (metadb).
5. Gerar credenciais e enviar e-mail de boas-vindas.

6) Infraestrutura e deploy (dev → staging → produção)
-----------------------------------------------------

10) Integração Python + Vue (padrões, autenticação, exemplos)
------------------------------------------------------------
Padrão recomendado: Vue (SPA) -> Backend Python (FastAPI) -> SuiteCRM API (V8)

Porque: Camada Python centraliza auth, billing, segurança e regras de negócio.
- Python faz cache do token OAuth2 (Redis) e renova.
- Vue nunca deve conter client_secret nem credenciais sensíveis.
- Use Celery para tarefas assíncronas (e.g. sincronização em massa).
- Use webhooks / logic hooks para eventos do SuiteCRM que notifiquem o seu backend.

Exemplo (Python) - obter token e listar contacts:

import requests

BASE = "https://crm.exemplo.com/Api/V8"
CLIENT_ID = "seu_client_id"
CLIENT_SECRET = "seu_client_secret"

def get_token():
    url = f"{BASE}/oauth2/token"
    payload = {
        "grant_type": "client_credentials",
        "client_id": CLIENT_ID,
        "client_secret": CLIENT_SECRET
    }
    r = requests.post(url, data=payload)
    r.raise_for_status()
    return r.json()["access_token"]

def get_contacts():
    token = get_token()
    headers = {"Authorization": f"Bearer {token}"}
    r = requests.get(f"{BASE}/module/Contacts", headers=headers)
    r.raise_for_status()
    return r.json()
